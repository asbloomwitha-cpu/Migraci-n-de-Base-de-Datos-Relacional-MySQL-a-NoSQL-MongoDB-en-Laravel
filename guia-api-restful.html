0. Crear el proyecto e instalar MongoDB (Si es nuevo)

Paso 0.1: Crear proyecto con Composer

composer create-project laravel/laravel nombre-proyecto

Paso 0.2: Entrar al directorio e instalar el paquete de MongoDB

cd nombre-proyecto
composer require mongodb/laravel-mongodb

Paso 0.3: Configurar base de datos MongoDB

Abrir el archivo .env y configurar la conexión a MongoDB:

DB_CONNECTION=mongodb
DB_HOST=127.0.0.1
DB_PORT=27017
DB_DATABASE=nombre_de_tu_base_de_datos
DB_USERNAME=
DB_PASSWORD=

Paso 0.4: Configurar `config/database.php`

Asegurarse de que exista la conexión mongodb en config/database.php:

'connections' => [
    'mongodb' => [
        'driver' => 'mongodb',
        'host' => env('DB_HOST', '127.0.0.1'),
        'port' => env('DB_PORT', 27017),
        'database' => env('DB_DATABASE', 'laravel_db'),
        'username' => env('DB_USERNAME', ''),
        'password' => env('DB_PASSWORD', ''),
        'options' => [
            'database' => env('DB_AUTHENTICATION_DATABASE', 'admin'),
        ],
    ],
],

📝 Nota sobre MongoDB: Al ser una base de datos NoSQL basada en colecciones de documentos JSON, no requiere ejecutar migraciones de tablas estructuradas (como en MySQL).

1. Diferencia entre routes/web.php y routes/api.php

routes/web.php

  • Para qué: Rutas para páginas web (HTML)
  • Usa: Sesiones, cookies, CSRF protection
  • Retorna: Vistas (Blade templates)
  • Ejemplo: Rutas para tu sitio web tradicional
  • URL: http://localhost:8000/ruta

routes/api.php

  • Para qué: Rutas para APIs (JSON)
  • Usa: Sin sesiones, sin cookies, sin CSRF
  • Retorna: JSON (datos)
  • Ejemplo: Endpoints para aplicaciones móviles, frontend separado (React, Vue, Angular)
  • URL: http://localhost:8000/api/ruta (prefijo /api automático)

Crear soporte para API en Laravel 11

⚠️ Importante: Laravel 11 ya NO incluye routes/api.php por defecto. Debes instalarlo:

php artisan install:api

2. Crear el Modelo Libro para MongoDB

php artisan make:model Libro

Abrir app/Models/Libro.php y extender de MongoDB\Laravel\Eloquent\Model:

<?php

namespace App\Models;

use MongoDB\Laravel\Eloquent\Model;

class Libro extends Model
{
    // Especificar la conexión y la colección de MongoDB
    protected $connection = 'mongodb';
    protected $collection = 'libros';

    // Campos que se pueden llenar masivamente
    protected $fillable = [
        'titulo',
        'autor',
        'genero',
        'anio_publicacion'
    ];
}
  • Para qué: Permite interactuar directamente con la colección `libros` de MongoDB utilizando Eloquent.

3. Crear el Controlador API

php artisan make:controller Api/LibroController
  • Para qué: Crea el controlador en app/Http/Controllers/Api/LibroController.php

4. Definir rutas en routes/api.php

⚠️ IMPORTANTE: Agregar el use del controlador al inicio del archivo:

<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\Api\LibroController;

Luego agregar las rutas:

GET Ruta 1 - Listar todos los libros

Route::get('/libros', [LibroController::class, 'index']);

POST Ruta 2 - Crear un libro

Route::post('/libros', [LibroController::class, 'store']);

GET Ruta 3 - Mostrar un libro específico

Route::get('/libros/{id}', [LibroController::class, 'show']);

PUT Ruta 4 - Actualizar un libro

Route::put('/libros/{id}', [LibroController::class, 'update']);

DELETE Ruta 5 - Eliminar un libro

Route::delete('/libros/{id}', [LibroController::class, 'destroy']);

5. Implementar métodos en el controlador

Archivo completo: app/Http/Controllers/Api/LibroController.php

<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\Libro;
use Illuminate\Http\Request;

class LibroController extends Controller
{
    /**
     * Obtiene todos los libros de la colección de MongoDB
     */
    public function index()
    {
        $libros = Libro::all();
        return response()->json($libros, 200);
    }

    /**
     * Crea un nuevo documento de libro en MongoDB
     */
    public function store(Request $request)
    {
        $validated =$request->validate([
            'titulo' => 'required|string|max:255',
            'autor' => 'required|string|max:255',
            'genero' => 'nullable|string|max:255',
            'anio_publicacion' => 'nullable|integer',
        ]);
        
        $libro = Libro::create($validated);
        return response()->json($libro, 201);
    }

    /**
     * Muestra un libro específico por su ID de MongoDB (ObjectId)
     */
    public function show($id)
    {
        $libro = Libro::findOrFail($id);
        return response()->json($libro, 200);
    }

    /**
     * Actualiza un documento de libro existente
     */
    public function update(Request $request,$id)
    {
        $libro = Libro::findOrFail($id);
        
        $validated =$request->validate([
            'titulo' => 'string|max:255',
            'autor' => 'string|max:255',
            'genero' => 'nullable|string|max:255',
            'anio_publicacion' => 'nullable|integer',
        ]);
        
        $libro->update($validated);
        return response()->json($libro, 200);
    }

    /**
     * Elimina un libro de MongoDB
     */
    public function destroy($id)
    {
        $libro = Libro::findOrFail($id);$libro->delete();
        
        return response()->json(null, 204);
    }
}

6. Códigos HTTP explicados - Para qué sirve cada uno

200 (OK)

  • Para qué: Decir "todo salió bien"
  • Cuándo: Al consultar o actualizar datos exitosamente

201 (Created)

  • Para qué: Decir "se creó algo nuevo correctamente"
  • Cuándo: Al crear un nuevo registro/documento en MongoDB

204 (No Content)

  • Para qué: Decir "se eliminó correctamente, no hay nada que mostrar"

404 (Not Found)

  • Para qué: Decir "no encontré lo que buscas"
  • Cuándo: Cuando el ObjectId no existe en la colección de MongoDB

422 (Unprocessable Entity)

  • Para qué: Decir "los datos que enviaste están mal"

7. Métodos Eloquent explicados - Para qué sirve cada uno

Libro::all()

  • Para qué: Traer todos los documentos de la colección `libros`

Libro::create($data)

  • Para qué: Insertar un nuevo documento JSON en MongoDB

Libro::findOrFail($id)

  • Para qué: Buscar un documento por su `_id` de MongoDB (ObjectId). Lanza 404 si no existe.

$libro->update($data)

  • Para qué: Actualizar los campos del documento en MongoDB

$libro->delete()

  • Para qué: Eliminar el documento de la colección

8. ¿Qué es un API RESTful?

Un API RESTful sigue los principios de la arquitectura REST (Representational State Transfer) independientemente de si usa bases de datos relacionales (MySQL) o NoSQL (MongoDB).

Principios que cumple esta API:

  1. Usa verbos HTTP correctamente: GET, POST, PUT, DELETE
  2. Usa recursos (sustantivos en plural): /api/libros
  3. Sin estado (Stateless): Cada petición es independiente
  4. Retorna códigos HTTP estándar: 200, 201, 204, 404, 422
  5. Intercambia datos en formato JSON

9. Probar cada ruta

Iniciar servidor de desarrollo

php artisan serve

Ejemplos de peticiones cURL:

GET 1. Ver todos los libros

curl http://localhost:8000/api/libros

POST 2. Crear un libro

curl -X POST http://localhost:8000/api/libros \
  -H "Content-Type: application/json" \
  -d '{"titulo":"Don Quijote","autor":"Miguel de Cervantes","genero":"Novela","anio_publicacion":1605}'

GET 3. Ver un libro específico (usando _id de MongoDB)

curl http://localhost:8000/api/libros/65f1a2b3c4d5e6f7a8b9c0d1

PUT 4. Actualizar un libro

curl -X PUT http://localhost:8000/api/libros/65f1a2b3c4d5e6f7a8b9c0d1 \
  -H "Content-Type: application/json" \
  -d '{"titulo":"Don Quijote de la Mancha"}'

DELETE 5. Eliminar un libro

curl -X DELETE http://localhost:8000/api/libros/65f1a2b3c4d5e6f7a8b9c0d1
